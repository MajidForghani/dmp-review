# Correctness audit of the all-demand implementations

## Yeh (2018)

The reconstruction follows Steps 0--2 and Lemmas 5--16: binary MPs are ordered
by logarithmic-prime value; Lambda sets prevent infeasible additions; cyclic
combinations are rejected; Lambda metadata is updated by Lemma 10; and sorted
candidate lists are merged. Exact vector equality confirms the paper's
floating-point logarithmic duplicate key.

It reproduces the paper's Fig. 1 and Tables II--VI counts 4, 5, 3, and 1 for
demands 1--4, including the valid 2-MP `(1,2,0,1,1,0)`. It agrees exactly with
the exhaustive oracle, Bai-2021, and repeated F-B-2017 on all validation
networks. It also produced the same output digest as Bai-2021 on all 37 final
study networks in the pre-release corpus audit.

Step 1.5 prints `j=|P_d|`, although `j` is not the outer loop variable. The code
uses the coherent interpretation `i=|P_1|`. This is an implementation-level
resolution of an apparent typographical error, not a new enumeration rule.

## Bai et al. (2021)

The reconstruction applies the paper's ordered binary-MP list, path and partial
vector infeasibility sets `Lambda`, the first-duplicate relation `rho`, the
nondecreasing component-index condition, cycle rejection, and exact duplicate
confirmation. It reproduces the paper's worked counts 8, 16, 8, and 1 for
demands 1--4 and the reported `Lambda`/`rho` behavior inherited from the earlier
line-by-line audit.

It agrees with Yeh-2018, repeated F-B-2017, and an independent exhaustive arc-state oracle
on the Yeh--Zuo example, four additional published examples, and 20 seeded
small random networks.

## Yeh and Zuo (2019): literal reconstruction

The code follows Steps 0--5: generate and sort `P1`, obtain `P_dmax`, descend
from `dmax-1` to 2, subtract every dominated 1-MP, and merge/deduplicate each
level. Exact tuples confirm equality after ordering; this prevents floating
point logarithmic-prime collisions without changing the candidate language.

The reconstruction reproduces the paper's own output counts 4, 4, 3, and 1.
That reproduction exposes a completeness problem. On Fig. 1, with

`Dmax = (3,2,1,1,1,2)`, 

the vector

`X = (1,2,0,1,1,0)`

is a valid 2-MP:

- it respects every component capacity;
- its maximum flow is exactly 2;
- decrementing any positive component reduces maximum flow below 2; and
- its positive support is acyclic.

Nevertheless, `X` is absent from the paper's reported `P2` and cannot be
generated by subtracting a 1-MP from a 3-MP. Thus the assertion that every
d-MP is contained in some `(d+1)`-MP, which is required by Lemma 9 and the
downward recurrence, is false under the ordinary componentwise d-MP definition.

The same literal method was incomplete on three of 20 small random oracle
networks and on several other published fixtures. The package therefore keeps
it as a diagnostic method but excludes it from primary speed rankings. Silently
supplementing its output with another enumerator would produce a different
algorithm and an invalid runtime comparison.

## Repeated fixed-d baseline

For every `d=1,...,dmax`, the package invokes the same independently validated
Forghani-elahabad and Bonani (2017) implementation used in the fixed-d study.
All preprocessing is repeated, matching the practical strategy whose cost the
reviewer asked us to compare with an all-demand method.
